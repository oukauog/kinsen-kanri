## 工事4a の範囲

### 4a-A. CSV 生成の純粋関数 + テスト（先に）
`js/csv.js` を新規作成（`window.Csv` / `module.exports`）。
- `escapeCell(v)` — カンマ・改行・ダブルクォートを含むセルを `"…"` で囲み、`"` は `""` に
- `paymentsCsv(group, payments, settlements)` → 文字列。列: `日付, メモ, 支払った人, 金額, 割り勘対象, 1人あたり, 清算状態`
  - 割り勘対象は名前を `・` で連結（v1 と同じ）
  - 清算状態: `未清算` / `清算済み（YYYY/MM/DD HH:mm）` / `金額確認中`
  - 並びは画面と同じ（日付降順 → createdAt 降順）
- `balancesCsv(group, payments, mode)` → 文字列。`mode` は `'unsettled'` か `'all'`。列: `メンバー, 払った合計, 負担分, 残高`。1 行目の前に `# 残高（未清算のみ）` または `# 残高（累計）` のコメント行を入れる。確認中はどちらのモードでも除外（工事3 と同じ）
- 先頭に UTF-8 BOM（`\uFEFF`）を付ける（Excel で開いたときの文字化け防止。v1 と同じ）
- `tests/csv.test.js`: エスケープ（カンマ・改行・引用符）、列の順、清算状態 3 種、BOM、未清算/累計の切替、0 件のときヘッダだけ。`node tests/run_all.js` 全通過まで先へ進まない

### 4a-B. 画面（`ui.js` / `index.html`、Python 経由）
- グループ画面の右上ボタン列に「CSV 出力」を復元し、v1 の CSV 出力モーダル（死に DOM）を再利用する。ボタン 2 つ: 「支払い一覧（CSV）」「残高（CSV）」。残高は**今の表示モード**（未清算のみ／累計）で出す旨をモーダル内に表示
- ファイル名: `<グループ名>_支払い_YYYYMMDD.csv` / `<グループ名>_残高_YYYYMMDD.csv`。ダウンロードは v1 の `downloadCSV` 相当（Blob + a[download]）
- 取込（xlsx/CSV）の UI は**今回は復元しない**（工事4b）。死に DOM はそのまま

### 4a-C. アプリ内ブラウザの案内（§5.1）
- `js/auth.js` または新規 `js/env.js` に `isInAppBrowser(ua)` を追加（純粋関数、Node からテスト可）。判定: UA に `Line/`、`Discord`、`FBAN` / `FBAV`、`Instagram`、`Twitter`、`MicroMessenger`、Android の `; wv)`、iOS で `Safari/` を含まない `Mobile/` のいずれか
- ログイン画面で真なら、「Google でログイン」ボタンの上に黄色の案内: 「このアプリ内ブラウザでは Google ログインができません。右上（または下）のメニューから **Safari / Chrome で開く** を選んでください」＋「URL をコピー」ボタン（`navigator.clipboard`、失敗時は URL を選択状態で表示）。ログインボタン自体は残す（誤判定のとき困るため）
- `tests/env.test.js`: 代表的な UA 文字列 8 本程度で真偽を固定（LINE iOS/Android、Discord、Instagram、通常の Safari iOS、Chrome Android、PC Chrome、PC Firefox）
