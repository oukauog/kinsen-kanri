## ケース2: 端数と境界

- 2 人で 1 円 → 各 0.5 の負担。残高 +0.5 / −0.5 は |残高|>0.5 に該当せず、清算は 0 本（v1 の閾値 0.5 の挙動）
- 3 人で 100 円（支払者含む）→ 負担 33.33…、支払者の残高 +66.67、他 2 人 −33.33。清算は 2 本、各 33 円（四捨五入）
- 支払者が割り勘対象に含まれない支払い（v1 の UI は支払者を自動で含めるので通常は起きない）→ v1 の calcBalances は支払者に何も加算せず、対象者から等分を引くだけ（残高合計が 0 にならない）。v1 の挙動固定テストではこの通りを期待値にし、v2 では UI とデータ検証で「支払者は必ず対象に含む」を保証する（calc.js の挙動は変えない）
- 割り勘対象 0 人の支払い → 無視（v1 と同じ）
- 金額確認中（pending）の支払い → 残高・清算から除外（工事3 で追加。v1 テストには含めない）
