## 現象（花井の検収で判明）
- PC（Chrome）: Google ログイン → グループ作成 → 支払い記録まで**正常**。認証後の実 DB 読み書きは通っている
- **iPhone Safari**: 「Google でログイン」を押すと `kinsen-kanri.firebaseapp.com` に遷移し、次の文言で止まる:
  `Unable to process request due to missing initial state. This may happen if browser sessionStorage is inaccessible or accidentally cleared. ... 2) Using signInWithRedirect in a storage-partitioned browser environment.`

## 原因（相談役の見立て）
- iOS Safari では `signInWithPopup` が失敗し、`auth.js` のフォールバックで `signInWithRedirect` に入っている
- `authDomain` が `kinsen-kanri.firebaseapp.com`（アプリの配信ドメイン `*.vercel.app` と別サイト）のため、Safari のストレージ分離（third-party storage partitioning）でリダイレクト認証の状態が引き継げない。Firebase 公式ドキュメント「Best practices for using signInWithRedirect on browsers that block third-party storage access」に該当する既知の問題
- 同じ理由で Safari では `signInWithPopup` も不安定になる

## 対策（Firebase 公式の Option 3「認証リクエストを自分のドメインで受けて firebaseapp.com へプロキシする」）
1. **`vercel.json` を新規作成**（リポジトリ直下）。Vercel の rewrites で `/__/auth/*` と `/__/firebase/*` を `https://kinsen-kanri.firebaseapp.com` の同じパスへ転送する:
   ```json
   {
     "rewrites": [
       { "source": "/__/auth/:path*", "destination": "https://kinsen-kanri.firebaseapp.com/__/auth/:path*" },
       { "source": "/__/firebase/:path*", "destination": "https://kinsen-kanri.firebaseapp.com/__/firebase/:path*" }
     ]
   }
   ```
2. **`js/firebase-init.js` の `authDomain` を、アプリ自身のホストにする**（Python スクリプト経由）:
   - `location.hostname` が `.vercel.app` で終わる場合（本番 `kinsen-kanri.vercel.app` とプレビュー）→ `authDomain: location.hostname`
   - それ以外（`localhost` 等、プロキシが無い環境）→ 従来どおり `kinsen-kanri.firebaseapp.com`
   - どちらを使ったかを `KKFirebase.authDomain` として公開し、コンソールに 1 行出す（検収で確認するため）
3. `auth.js` のフォールバック条件は変えなくてよい。ただし `getRedirectResult()` の失敗時トーストは、`auth/missing-initial-state` 系のエラーを含めて文言が画面に出ることを確認する
4. `tools/check_wiring.py`・`py -X utf8 tools/make_uitest.py` の通し確認・`node --check`・`node tests/calc.test.js` を回してから push
