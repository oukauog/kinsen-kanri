## 2. データの持ち方と表示順の決めごと（実装したとおり）

**データ**
- `users/{uid}/groups/{code}` に `order`（数値）を足し、`{ joinedAt, order? }` の形にしました
- `groups/{code}` 側には何も書きません
- `users/{uid}` は本人だけが読み書きでき、中身の検証も無いルールです。そのためルールは変更していません
- `order` の無い既存のグループ（今あるものすべて）はバックフィルしていません。並べるときだけ `joinedAt` を代わりに使います

**表示順のキー**（`js/group_order.js` の `sortKey` / `sortCodes`）
- `order` が数値なら `order` を使います
- 無ければ `joinedAt` を使い、それも無ければ 0 とします
- 昇順に並べ、同点はコードの文字列順にします（`localeCompare` ではない単純な文字列比較）
- `order` が文字列や null のときは「無いもの」として扱います
- 依頼文の「typeof order === 'number'」に加えて、NaN と Infinity も「無いもの」にしています（`isFinite`）。並べ替えの比較が壊れないようにするためです

**新規作成・コード参加**（`nextOrder`）
- `order` は「今の自分の一覧の表示順キーの最大 + 1」で、一覧が空なら 0 です
- 計算は ui.js が `myGroups` から行い、`Store.createGroup(name, members, order)` / `Store.joinGroup(code, order)` に渡します
- store.js はこれを `joinedAt` と一緒に 1 回の `set` で書きます（order が数値でなければ書かず、今までどおり `{ joinedAt }` だけになります）
- 旧データの移行（`migrateRoom`）は触っていません。移行で入るグループは `order` 無し、つまり `joinedAt` 順です

**ドラッグ＆ドロップ**（`Store.setGroupOrder(codes)`）
- 並びが確定したら、そのときの DOM の順（`data-code`）で全グループに `order` = 0, 1, 2, … を書きます
- 書き込みは `users/{uid}/groups` への 1 回の `update`（キーは `<code>/order`）です。`joinedAt` には触れず、`wrapWrite` で包んでいます
- 失敗は既存の `fail(...)` でトーストに出します
- ドロップ直後に手で並べ直す処理はありません。Firebase から戻ってくる更新で `watchMyGroups` → `renderSidebar` が走り、同じ順で描き直されます
- 1 点だけ依頼文に足しています。ui.js の `saveGroupOrder` で、書く前に「今の一覧（myGroups）にあるコード」だけに絞りました。描画とドロップの間に別の端末で退出したグループがあっても、`order` だけのノードが作られないようにするためです

仕様書 `docs/10_仕様書_v2再設計.md` の §3 は、`{ joinedAt, order? }` に直して上の決めごとを 1 段落足しました。`js/store.js` 冒頭のデータモデルのコメントも同じく直しています。

## 7. 気づいた点（直していないもの）

- **iPhone のドロワー内でのドラッグ（要実機確認）**:
  - スマホのドロワー（`.sidebar`）は `transform: translateX(...)` と `transition` で出し入れしています
  - SortableJS はタッチ操作では、ドラッグ中の行の複製を自前で描く方式（fallback）で動きます。変形（transform）の掛かった親の中では、複製の位置が指からずれるという報告が過去の版であります
  - 1.15 系は親の transform を計算に入れるので問題ないと見ていますが、ヘッドレスでは確かめられません
  - 指と行がずれる・ドラッグが途中で切れる場合は、`fallbackOnBody: true`（複製を body に置く）や `forceFallback: true` を試す余地があります。今回は入れていません
- **ドラッグ中に一覧が描き直されると、そのドラッグは途切れます**:
  - 他のメンバーがグループ名を変えた（meta の更新）などで `renderSidebar` が `innerHTML` を置き換えると、つかんでいる行が DOM から外れます
  - 頻度は低いと見て、対策（ドラッグ中は描き直しを保留する等）はしていません
- **保存に失敗したとき**: トーストは出ますが、画面の並びはドロップした順のまま残ります（元の順に戻す処理はありません）。再読み込み・次の描き直しで保存されている順に戻ります
- **order の値が大きくなることがある**:
  - order の無い既存グループがある状態で新規作成・参加すると、その order は「最大の joinedAt + 1」（13 桁の時刻の数）になります
  - 表示順としては正しく一番下に入ります。一度でもドラッグで並べ替えれば 0..n-1 に揃います
- **2 台で同時に並べ替えた場合**: 後から保存した方の順になります（`update` で全件の order を書くため）
- **仕様書 §5.2 に「`users/{uid}/groups` に登録されたグループを名前で一覧」と残っています**。今回の並び順と食い違いますが、依頼の範囲（§3 の修正）の外なので直していません（**要判断**: §5.2 を「自分で決めた順（§3）で一覧」に直してよいか）
