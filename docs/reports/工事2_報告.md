## 4. 仕様からずらした点と理由

| # | ずらした点 | 理由 |
|---|---|---|
| 1 | `convertRoom` の戻り値に `order`（コードの並び。引き継ぐグループが先頭）と `skipped.noCodeGroups` を足した | 書き込み順を決めるのと、新コードが足りないとき（呼び出し側の数え間違い）に黙ってデータを落とさないため。依頼文の 3 つの `skipped` はそのまま |
| 2 | メンバー ID・支払い ID は**旧データのものをそのまま使う**（Firebase のキーに使えない文字が入っていたときだけ振り直し、参照も差し替え） | 支払いの `payerId` / `participants` がそのまま生きる。ID を振り直すと対応表の取り違えで金額が狂うリスクがある |
| 3 | `summarizeRoom` / `countGroups` を追加 | 選択ダイアログに「メンバー数・支払い件数」を出すため。変換とは別の純粋関数にしてテストを分けた |
| 4 | 移行レコードの時刻は**クライアントの `Date.now()`**（他の書き込みはサーバ時刻 `ServerValue.TIMESTAMP`） | `convertRoom` を純粋関数にするため（依頼文の `opts.now`）。表示に使うのは支払いの `date` なので実害は無いと判断。気になるなら要判断 §7-5 |
| 5 | 削除済みグループに属する支払いは `orphanPayments` に数える | 「取り込まれない支払い」を 1 つの数字で説明できるようにするため。`deletedPayments` は「支払い自身が削除済み」だけを数えます |
| 6 | 日付が無い支払いは `date: ''` のまま取り込む | 勝手に日付をでっち上げない。履歴では日付欄が空で先頭に並びます（v1 にも無い想定） |
| 7 | 書き込みエラーの通知を `store.js` に集約し、`ui.js` 側は「通知済みの印」を見て二重トーストを避ける | 依頼文の「すべての書き込みを `.catch` で拾う」を、抜けが出ない形（データ層で包む）で満たすため |

## 7. 要判断・申し送り

1. **本番移行（`Y39EN6`）で誰が最初に参加するか**。最初に参加した人が全グループの `createdBy` になり、**2 件目以降のグループの新コードはその人の画面にしか出ません**。旧ルームに広島旅行以外のグループが混ざっている場合、その新コードを控えて他の人に配る役が要ります。→ **花井が最初に参加して、新コードを控えてから友人に案内する**のが安全だと思います
2. **`Y39EN6` の中身を事前に確認したい**（グループが何件あるか、削除済みがどれだけあるか）。今回は読んでいません（依頼で禁止）。本番移行の前に、相談役か花井が `rooms/Y39EN6` を 1 回読んで「グループ 1 件だけか」を確かめておくと、ダイアログがどちらの型（確認 or 選択）になるか分かります
3. **移行後も旧アプリ（v1）は動き続ける**点。友人が古い URL を開いて支払いを足すと、v1 は `rooms/Y39EN6` に書き、v2 側には反映されません（データが割れる）。§8 の本番切替で `rooms` を読み取り専用にすると v1 の保存は失敗しますが、v1 は端末内では動き続けます。**切替日を決めて「この日から新しい URL で」と案内する**のがよいと思います
4. **同時参加のときの二重移行**。`meta` を transaction で取り合う作りにしてあり、負けた側は「参加のみ」になります（結果ダイアログに「すでに取り込み済みでした」と出ます）。ただし**実 DB では未検証**です。心配なら本番移行時は「花井が先に 1 人で参加 → 完了を確認してから友人に案内」の順にすれば、この経路自体を通りません
5. **移行レコードの時刻がクライアント時刻**（§4-4）。サーバ時刻に揃えるべきなら、`convertRoom` の `now` を使わず書き込み時に `ServerValue.TIMESTAMP` へ差し替える改修が要ります（純粋関数のテストしやすさとのトレードオフ）
6. **孤児支払いを捨ててよいか**。fixture では 2 件出ます。実データで多い場合、「取り込めなかった支払い」を別グループにまとめて救済する案もあります（工事4 で検討可能）
7. **`rooms` の読み取りルール**。開発中ルールでは未ログインでも `rooms` が読めます（今回の確認で判明）。本番切替時に `".read": "auth != null", ".write": false` にすれば、移行フローはそのまま動きます（実装は認証後にしか読みません）
8. **`docs/fixtures/` を git に置いた**こと（検収の再現性のため）。不要なら外します
