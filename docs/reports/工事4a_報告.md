## 4. 仕様からずらした点と理由

| # | ずらした点 | 理由 |
|---|---|---|
| 1 | セルは**必要なときだけ**引用符で囲む（v1 は全セルを囲んでいた） | 依頼文の `escapeCell` の定義どおり。Excel でも Google スプレッドシートでも同じように開けます |
| 2 | 残高 CSV に「払った合計・負担分・残高」の 3 列（v1 は「残高・状態」の 2 列） | 依頼文の列指定どおり。v1 の「状態」（多く払っている等）は落としました。必要なら戻せます |
| 3 | 残高 CSV の数値は**整数に丸めて**出す | 負担分は割り算で端数が出る（例 58433.08…）。表計算で扱いやすい整数にしました。丸めない生の値が要るなら要判断 |
| 4 | 金額確認中の支払いは、金額列に**保存値の 0** を出す（清算状態の列に「金額確認中」） | 空欄にすると数値列に穴が空くため。金額が未確定であることは状態列で分かります |
| 5 | 支払い CSV の並びは**日付の降順**（画面と同じ。v1 の CSV は昇順だった） | 依頼文の「並びは画面と同じ」に従いました |
| 6 | `exportPaymentsCsv` / `exportBalancesCsv` とは別に、**中身だけ作る** `buildPaymentsCsv` / `buildBalancesCsv` を用意した | ヘッドレスではダウンロードを確かめられないので、中身を無人で検査できるようにするため |
| 7 | アプリ内ブラウザの案内は、**ログインボタンの上**に出し、ボタンは残す | 依頼文どおり（誤判定でログインできなくなるのを避けるため）。`navigator.clipboard` が使えない環境では URL を画面に出して手で選べるようにしています |
| 8 | 判定に iOS の「`Mobile/` があるのに `Safari/` が無い」を入れた | 依頼文の指定どおり。アプリ名を名乗らない WebView（Discord iOS など）を拾うため。副作用として、UA を細工した特殊なブラウザでも案内が出ることがありますが、ボタンは残るので実害はありません |
