## 3. `authDomain` の切替ロジック

```js
var FALLBACK_AUTH_DOMAIN = "kinsen-kanri.firebaseapp.com";

function pickAuthDomain(hostname) {
  var h = String(hostname == null ? '' : hostname);
  return /\.vercel\.app$/i.test(h) ? h : FALLBACK_AUTH_DOMAIN;
}

var authDomain = pickAuthDomain(root.location && root.location.hostname);
```

- `kinsen-kanri.vercel.app`（本番）、`kinsen-kanri-git-v2-….vercel.app`（プレビュー）→ **自分のホスト**。
  ブラウザから見ると「アプリも認証も同じサイト」になるので、Safari のストレージ分離の影響を受けない
- `localhost` / `127.0.0.1` / それ以外 → **従来どおり `kinsen-kanri.firebaseapp.com`**（プロキシが無い環境なので、自分のホストにすると逆に壊れる）
- ホスト名が空・`undefined` でも落ちずに従来値になる
- 起動時にコンソールへ 1 行出ます:
  `[kinsen-kanri] authDomain = kinsen-kanri.vercel.app（自分のドメインでプロキシ）`
  / `… = kinsen-kanri.firebaseapp.com（従来どおり）`
- `window.KKFirebase.authDomain` でも読めます（検収時、コンソールに `KKFirebase.authDomain` と打てば確認できます）

## 5. 期待する動き（なぜこれで直るか）

1. iPhone Safari で「Google でログイン」→ `signInWithPopup` が失敗 → `signInWithRedirect` に入る（ここは従来どおり）
2. SDK は `https://<authDomain>/__/auth/handler` に遷移する。`authDomain` が**自分のホスト**になったので、
   遷移先は `https://kinsen-kanri.vercel.app/__/auth/handler`（＝同じサイト）

Google 側の OAuth リダイレクト URI（`https://kinsen-kanri.firebaseapp.com/__/auth/handler`）は変わらないので、
**Google Cloud コンソール側の設定変更は不要**の想定です（もし `redirect_uri_mismatch` が出たら、そこが想定と違います。§7-3）。
