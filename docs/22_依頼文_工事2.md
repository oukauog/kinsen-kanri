## 旧ルームの形（v1 が書いたデータ）
```
rooms/{code} = {
  groups:   [ { id, name, members: [ { id, name }, ... ] }, ... ],   // 配列。複数グループが混ざることがある
  payments: [ { id, groupId, date, memo, payerId, amount, participants: [mid, ...] }, ... ],
  deletedGroupIds:   [ id, ... ],   // 無いこともある
  deletedPaymentIds: [ id, ... ],   // 無いこともある
  updatedAt: number
}
```
- `participants` は配列。支払者は通常含まれているが、含まれていなくてもそのまま保つ（`Calc` の v1 互換の挙動に任せる）
- `deletedGroupIds` / `deletedPaymentIds` に載っている ID のグループ・支払いは**取り込まない**
- どのグループにも属さない支払い（`groupId` が groups に無い）は取り込まず、件数だけ報告に残す

## 工事2 の範囲

### 2-A. 移行ロジック（純粋関数）+ 固定テスト（先に）
- `js/migrate.js` を新規作成。DOM・Firebase に依存しない純粋関数。ブラウザは `window.Migrate`、Node は `module.exports`
  - `convertRoom(room, opts)` — 旧ルーム 1 件を v2 の書き込み用オブジェクトに変換する
    - `opts = { code, uid, pickGroupId, newCodes: [..], now }`
    - `pickGroupId` のグループが `code` を受け取る。残りのグループは `newCodes` から順にコードを割り当てる
    - 戻り値: `{ groups: { <code>: { meta, members, payments } , ... }, skipped: { deletedGroups, deletedPayments, orphanPayments } }`
    - `meta = { name, createdAt: now, createdBy: uid, schemaVersion: 2, migratedFrom: 'rooms/' + 元code, migratedAt: now }`
    - `members[mid] = { name, order }`（配列順を order に）
    - `payments[pid] = { date, memo, payerId, amount(整数化), participants: {mid:true}, settlementId: null, pending: false, createdBy: uid, createdAt: now, updatedAt: now }`（`Calc.normalizeParticipants` を使う）
    - 入力が壊れていても例外で落ちず、取り込めるものだけ取り込む（`groups` が無い・空 → 結果も空）
- `tests/migrate.test.js`（Node 標準 `assert`）。ケース: ①1 グループ・数件 ②3 グループ混在で `pickGroupId` に code が付き残りに新コード ③deletedGroupIds / deletedPaymentIds の除外 ④孤児支払いの除外 ⑤participants 配列→オブジェクト ⑥groups 欠落・payments 欠落でも落ちない。**通過するまで先へ進まない**

### 2-B. 参加フローへの組み込み（`store.js` / `ui.js`、Python 経由）
- 「コードで参加」でコードを入力したときの分岐:
  1. `groups/{code}/meta` が**ある** → 従来どおり参加（変更なし）
  2. 無い → `rooms/{code}` を 1 回だけ読む
     - 無い → 従来どおり「そのコードのグループは見つかりませんでした」
     - ある → **移行フロー**へ
- 移行フロー:
  - 旧ルームの `groups` が 1 件 → 確認ダイアログ「旧バージョンのデータが見つかりました。『<名前>』（支払い N 件）を取り込んで参加しますか？」→ 取り込む
  - 2 件以上 → 選択ダイアログ「このコードには複数のグループがあります。コード <code> を引き継ぐグループを 1 つ選んでください（他のグループには新しいコードを発行します）」→ ラジオで選択（名前・メンバー数・支払い件数を表示）→ 取り込む
  - 取り込み: 新コードは `store.js` の既存ロジック（6 桁・重複チェック）で必要数だけ発行 → `convertRoom` → **書き込み順序はルールに合わせる**: 先に `users/{uid}/groups/{各code}` を登録 → その後 `groups/{各code}` を `update` で書く。`meta` は `transaction` で「null のときだけ書く」にして、同時参加で二重移行にならないようにする（先に書かれていたら移行をやめて通常参加に切り替える）
  - 完了後、結果ダイアログ: 取り込んだグループ名とコードの一覧（新コードはコピーできるように）、除外した件数（削除済み・孤児）。「閉じる」で選んだグループを開く
  - 失敗（権限エラー・通信断）時: 赤いトーストで理由を表示し、`users/{uid}/groups` に登録済みのものがあれば取り消す（部分成功を残さない）
- **`rooms/{code}` には何も書かない**（読み取りのみ）
