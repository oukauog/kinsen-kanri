## 工事3 の範囲

### 3-A. 純粋ロジック + 固定テスト（先に）
`js/settle.js` を新規作成（`window.Settle` / `module.exports`）。DOM・Firebase に依存しない。
- `pickUnsettled(payments)` → `settlementId == null` かつ `pending != true` の支払いだけを返す（計算対象）
- `pickPending(payments)` → `pending == true` の支払い（金額確認中）
- `buildSettlement(groupMembers, payments, opts)` — `opts = { uid, now }`。`pickUnsettled` した支払いで `Calc.calcBalances` / `Calc.calcSettlement` を回し、次を返す:
  - `settlement = { createdAt: now, createdBy: uid, transfers: { tid: { from(mid), to(mid), fromName, toName, amount, done: false } }, paymentIds: { pid: true } }`
  - `transfers` が 0 本、または対象支払いが 0 件なら `null` を返す（確定できない）
  - 工事1 で `calcSettlement` の戻り値に足した `fromId` / `toId` を使う
- `latestSettlement(settlements)` → `createdAt` 最大の 1 件（無ければ null）
- `canUndo(settlements, sid)` → その sid が最新の 1 件のときだけ true
- `hasAnyDone(settlement)` → 送金チェックが 1 つでも入っていれば true
- `tests/settle.test.js`（Node 標準 `assert`）: ①未清算だけが対象になる（清算済み・確認中は除外） ②確定ペイロードの形と `paymentIds` の中身 ③貸し借りなし・対象 0 件で null ④最新判定と取り消し可否 ⑤`docs/30_テストケース_清算.md` ケース1 の 36 件を一度清算してから 3 件足すと、2 回目の清算が「足した 3 件だけ」で計算される
- `node tests/run_all.js` が全通過するまで先へ進まない

### 3-B. データ操作（`store.js`、Python 経由）
- `confirmSettlement(code, settlement)` — `groups/{code}` に対する **1 回の多パス `update`** で、`settlements/{sid}` を書き、対象の `payments/{pid}/settlementId` を sid にする（原子的に）
- `setTransferDone(code, sid, tid, done)` — `transfers/{tid}/done`、`doneAt`（サーバ時刻 or null）、`doneBy`（uid or null）を更新
- `undoSettlement(code, sid, paymentIds)` — 1 回の多パス `update` で `payments/{pid}/settlementId` を null に戻し、`settlements/{sid}` を削除
- **ロックの防波堤**: `updatePayment` / `removePayment` は、対象の支払いに `settlementId` が入っていたら書かずに拒否し、`onWriteError` 経由で「清算済みの支払いは編集できません。先に清算を取り消してください」を出す（UI で無効化するだけでなくデータ層でも止める）
- 支払いの新規作成・更新で `pending`（bool）と `amount` を扱えるようにする。`pending: true` のときは `amount` は 0 を保存する

### 3-C. 画面（`ui.js` / `index.html` / `css/v2.css`、Python 経由）
**支払い入力モーダル（§5.3.1）**
- 「金額確認中」チェックボックスを金額欄の直下に追加。☑ のとき金額欄は空でも登録可（プレースホルダ「あとで入力」）、☐ のときは従来どおり 1 円以上必須
- 履歴の行: `pending` は**薄黄色**の背景、金額欄に「確認中」。編集で金額を入れて ☐ に戻せば通常の支払いに
- 履歴の行: `settlementId` あり は**薄いグレー**、✏ と ✕ は無効（ツールチップ「清算済み」）。行に小さく「清算済み」バッジ

**残高カード（§5.4）**
- 既定は**未清算分**（`pickUnsettled`）で計算。見出しの右に「累計を見る／未清算のみ」の切替トグル。選択は `kk_v2_balanceMode` に保存
- 確認中の支払いが 1 件以上あれば、残高の見出し脇に「金額確認中 N 件（計算に含まれていません）」の小さな注記

**清算モーダル（§5.5）**
- 上段「今回の清算」: `buildSettlement` の送金リスト。確認中の支払いが 1 件以上あれば**黄色の警告**「金額確認中の支払いが N 件あります。金額を確定してから清算してください」＋該当メモの一覧を出し、「この内容で清算する」ボタンを**無効化**。確認中が 0 件で送金が 1 本以上なら有効
- 「この内容で清算する」→ 確認ダイアログ（対象 N 件、送金 M 本）→ `confirmSettlement` → トースト「清算を記録しました」
- 対象支払い 0 件 or 送金 0 本のときは「未清算の貸し借りはありません」と表示し、ボタンは出さない
- 下段「過去の清算」: `createdAt` 降順。各清算に日時、送金一覧（1 本ごとにチェックボックス ☑＝払った。`setTransferDone`。他端末にもリアルタイム反映）、全部 ☑ なら「完了」バッジ、対象件数
- 最新の 1 件だけに「この清算を取り消す」ボタン。`hasAnyDone` なら確認ダイアログの文言を強める（「送金チェックが入っています。本当に取り消しますか？」）。古い清算には「取り消せるのは最新の清算のみです」と薄字
- 旧「※ この清算はまだ記録されません（清算の記録は工事3 で追加）」の注記は撤去
